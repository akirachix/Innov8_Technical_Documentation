## Commit messages

Document the actual commit format.

```text
<type>: <short description>
```

Example categories may include `feat`, `fix`, `docs`, `refactor`, `test`, and `chore`, but only keep categories the repository actually uses.

## Pull requests

A PR should explain:

- what changed
- why it changed
- how it was tested
- screenshots for UI changes
- database changes
- API changes
- environment changes
- documentation changes
